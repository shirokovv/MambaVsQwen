Mamba vs Qwen: сравнение языковых моделей
=======================================

## О проекте

Приложение сравнивает Falcon3-Mamba-7B-Base и Qwen3-8B-Base на бенчмарке LAMBADA: модели оценивают последнее слово отрывка по предыдущему тексту. Мы исследуем, как различаются качество и время обработки у архитектур Mamba и Transformer.

Обе модели работают через MLX на Apple Silicon с 4-битным квантованием и размером группы 64. Интерфейс разработан на Python с использованием Streamlit.

## Возможности приложения

- **Выбор эксперимента:** одна модель или обе, 10, 100, 1000 примеров либо полный тест.
- **Оценка качества:** accuracy и perplexity по стандартному протоколу `lambada_standard`, без чат-шаблонов и дополнительных примеров.
- **Измерение времени:** длительность оценки и среднее число секунд на пример.
- **История:** сохранение результатов и параметров в SQLite, чтение после перезапуска.
- **Сравнение:** три интерактивных графика с фильтрами по моделям, размерам выборки и запускам.

## Структура проекта

- `app/` — интерфейс, HTTP-клиенты моделей, классы эксперимента и результата, работа с базой и графиками. Здесь же находятся зависимости и конфигурация Docker для приложения.
- `inference/` — модельный HTTP-сервер, подготовка LAMBADA и весов, зависимости MLX. Окружение, модели и логи создаются локально.
- `data/` — кеш Hugging Face, метаданные датасета и база экспериментов. Создаётся автоматически и не включается в Git.
- `start.sh` — подготовка зависимостей и запуск моделей и интерфейса.
- `stop.sh` — остановка приложения и модельных процессов с сохранением данных.

## Запуск

Нужен Mac с Apple Silicon, Python 3.13, Docker CLI, Docker Compose и Colima. Проект проверялся на Apple M4 с 24 ГиБ общей памяти. Для первой подготовки нужны интернет и свободное место под исходные и квантованные веса.

Из корня проекта:

```bash
colima start --profile mas-local
./start.sh
```

При первом запуске скрипт скачивает датасет и модели, конвертирует Mamba и подготавливает окружение. Qwen загружается уже в MLX 4-bit формате. Модели работают нативно на macOS, интерфейс — в Docker на локальном порту 8501. При повторном запуске подготовленные файлы используются снова.

Остановка:

```bash
./stop.sh
```

## Используемые библиотеки

- **MLX и MLX-LM** — загрузка моделей и вычисления на GPU через Metal.
- **lm-eval, datasets и Hugging Face Hub** — стандартная оценка, датасет и загрузка весов.
- **Streamlit, Pandas и Plotly** — интерфейс, таблицы и интерактивные графики.
- **sqlite3 и http.server** — хранение результатов и HTTP-серверы на стандартной библиотеке Python.

## Ограничения

- Текущий запуск рассчитан на macOS с Apple Silicon.
- Модели различаются не только архитектурой, но и обучением, размером и токенизаторами. Результат нельзя переносить на все Mamba и Transformer.
- Perplexity оценивает последнее слово LAMBADA, а время включает весь вызов оценки, но не первоначальную загрузку весов.
- Короткие отрывки LAMBADA не заменяют отдельную проверку длинного контекста и скорости генерации.
